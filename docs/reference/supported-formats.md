# Supported formats

Four sliced-file formats, each behind its own Cargo feature.

| Format | Extension | Feature | Produced by |
|---|---|---|---|
| Bambu Studio 3MF | `.gcode.3mf` | `bambu-3mf` | Bambu Studio, OrcaSlicer |
| Plain-text G-code | `.gcode` | `gcode` | PrusaSlicer, OrcaSlicer, SuperSlicer, most FDM slicers |
| PrusaSlicer binary G-code | `.bgcode` | `prusa-bgcode` | PrusaSlicer |
| PrusaSlicer SLA | `.sl1`, `.sl1s` | `prusa-sl1` | PrusaSlicer (resin) |

`bambu` and `prusa` are umbrella features pulling in every format for
that vendor. The default is `["bambu", "prusa"]`, which builds all four.

```sh
cargo install printcalc --no-default-features --features prusa-sl1
cargo add libprintcalc --no-default-features --features gcode
```

A file whose format isn't compiled in fails with `not this parser's
format` — the same error an unrecognized file gives, since the parser
that would have claimed it isn't there to say so. If a file that should
work doesn't, check your feature flags before suspecting the file.

## What gets read

Every parser produces the same `SliceSummary`: one entry per plate with a
print time and per-slot material usage, plus file-wide metadata used to
identify the printer and filaments.

Costing needs only print time and material used. Everything else feeds
[auto-detection](../explanation/conservative-matching.md), which is why a
format that reports less still costs correctly — it just asks more of you.

### Always present

| Field | Meaning |
|---|---|
| `print_time_seconds` | The slicer's own prediction, per plate. |
| `grams` or `ml` | Material used per slot, per plate. |

### File-wide metadata (`SliceSummary::meta`)

| Field | Bambu 3MF | G-code / bgcode | SLA |
|---|---|---|---|
| `printer_profile` | ✓ | ✓ | ✓ |
| `print_profile` | ✓ | ✓ | ✓ |
| `printer_variant` | ✓ | ✓ | ✓ |
| `nozzle_diameter` | ✓ | ✓ | — (no nozzle) |
| `slicer` name and version | ✓ | ✓ | ✓ |

### Per-slot metadata (`FilamentUsage`)

| Field | Bambu 3MF | G-code / bgcode | SLA |
|---|---|---|---|
| `slot_id` | AMS tray id | extruder index | single slot |
| `material_type` | ✓ | ✓ | ✓ (family) |
| `profile_name` | ✓ | ✓ | ✓ |
| `vendor` | ✓ | ✓ | ✓ |
| `color` | ✓ | ✓ | ✓ |
| `price` | ✓ | ✓ | see [SLA pricing](#sla-pricing) |
| `density` | ✓ | ✓ | ✓ |
| `meters` | ✓ | ✓ | — |

A `price` read from the file is the slicer's own configured spool price.
It is what lets a job cost correctly when no stored profile matches.

## Format notes

### Bambu Studio 3MF

A ZIP archive. Print times and per-slot usage come from
`Metadata/slice_info.config` (XML); filament profile names, vendors,
prices and densities come from `Metadata/project_settings.config` (JSON),
where each setting is an array indexed by AMS tray. Tray `id` is
1-based; the arrays are 0-based, and the parser accounts for the offset.

This is the only format that can hold **multiple plates** in one file.
Each is costed separately or together — see
[`--plate`](cli.md#job-inputs).

The slicer version comes from the `X-BBL-Client-Version` header, giving
strings like `BambuStudio 02.07.01.62`.

### Plain-text G-code

Read from the PrusaSlicer-lineage `; key = value` comment block that most
FDM slicers emit. The slicer name comes from the `generated by` banner.

Per-slot values are positional lists, and the two list separators differ:
text lists (`filament_settings_id`, `filament_vendor`) are `;`-separated,
numeric lists (`filament_cost`, `filament used [g]`) are `,`-separated. A
single `filament_vendor` with several slots applies to all of them.

Because this reads a comment convention rather than a strict format, a
slicer that omits a key simply yields less metadata. It never fails the
parse.

### PrusaSlicer binary G-code

The same metadata as plain-text G-code, read out of `.bgcode`'s
compressed config blocks. Everything above applies unchanged.

### PrusaSlicer SLA

A ZIP archive. Print time, used material and layer height come from
`config.ini`; the material profile name, vendor, color, density and
bottle price come from `prusaslicer.ini`.

`material_type` is the family (`"Model"`), consistent with FDM reporting
`"PLA"`; the full preset name is in `profile_name`.

Resin is measured in **milliliters**, not grams, and priced per liter.
A resin job needs a `resin` printer profile and a `resin` material
profile; mixing kinds is rejected.

#### SLA pricing

PrusaSlicer stores resin price as a bottle cost and a bottle volume,
which the parser converts to a price per liter:

```
price_per_liter = bottle_cost × 1000 / bottle_volume_ml
```

A `bottle_cost` of `0` — PrusaSlicer's default, and what most stock
presets ship with — means **unpriced**, not free. Such a slot is left
without a price, so unless a stored profile matches it by name, costing
fails naming the slot rather than pricing the resin at zero.

In practice most SLA files need either a saved resin profile or an
explicit `--filament`.
